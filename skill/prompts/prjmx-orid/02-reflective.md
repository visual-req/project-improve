# R · Reflective（主观感受/摩擦点）

目标：把 O 段事实翻译为团队层面的“感受与摩擦点”，用于引导讨论与聚焦，而不是归因。

## 规则

- 不归因个人，不评价“谁做得不好”
- 用过程语言描述：排队、阻塞、返工、上下游依赖、切换成本、信息不对称
- 每条感受必须能映射回某一条 O 段事实（用括号标注引用）

## 输出（建议 5–10 条）

示例模板：

- 感受：我们在 {阶段/泳道} 上排队严重，导致交付节奏不稳定（对应：{O-2：Cycle Time p75 上升}）
- 感受：质量问题更像“交付后返工”，影响了计划可靠性（对应：{O-5：Escaped Defects 增加 / Reopen Rate 上升}）
- 感受：评审与协作反馈延迟导致任务长时间停滞（对应：{O-7：Review Latency p75 较高}）

## 输出格式

输出 `orid.reflective` 数组（字符串即可），并确保每条都包含对应的 O 段引用。
