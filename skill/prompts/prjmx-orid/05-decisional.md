# D · Decisional（决策/行动方向）

目标：把原因假设收敛为决策方向与行动原则，为下一步生成可排期行动项做准备。

## 输入

- O 段事实（指标/趋势/异常样本）
- I 段假设（含验证方式）
- 5 Whys（若已执行，优先使用其“杠杆点”）

## 输出内容

输出 6–10 条决策点，覆盖：

- 优先级：先解决瓶颈与质量外溢，再优化局部效率
- 约束：不以不可持续加班换指标
- 节奏：定义复盘频率与检查窗口（下一窗口对比）
- 机制：WIP 约束、入口 DoR/DoD、评审 SLA、阻塞原因标签等
- 验证：每个方向至少绑定 1 个指标与最低可接受变化

同时必须体现“过程完整性”：

- 前置质量达标：需求/验收标准、设计决策（ADR/契约）、测试策略、评审与 CI 门禁是否缺失；缺失则优先补齐，而不是只做后置修补
- 透明性信号：把可见的阻碍点（堆积/等待/失败聚类/门禁失败）变成制度化的触发条件与响应机制

并显式考虑“基线拉升/自动化/复用”：

- 基线拉升：把本次有效做法固化为默认机制（模板/门禁/自动检查/指标阈值），避免“靠人记住”
- 自动化技术：自动化测试、CI/CD 自动门禁、自动回归与发布策略（灰度/回滚）优先于手工检查
- 复用：优先寻找可复用的组件/脚手架/共享库/检查清单，减少重复劳动

可选加入“AI 赋能”方向（不替代责任，只降低成本与遗漏）：

- 结构化：把需求/设计/变更/验收/风险字段化，便于跟踪与复盘
- 检查清单：对缺口/风险做自动提示（尤其是需求、设计、发布、监控）
- 归因聚类：对失败/告警/返工做聚类，定位高频模式
- 行动项草稿：输出行动项草稿但必须包含负责人/验收方法/验证窗口

## 输出格式

输出 `orid.decisional` 数组（字符串即可），建议用动词开头：

- “限制 {泳道} WIP，并建立每日清理机制（验证：cycle time p50 ≤ X）”
- “把缺陷前移到评审/测试阶段（验证：escaped defects ≤ Y）”
