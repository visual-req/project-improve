# 行动项与跟踪

行动项的目的不是“写一堆任务”，而是把 D 段的决策方向变成可执行、可验收、可复盘的计划，并能在后续窗口对比中判断是否真的改善了质量与交付。

## 从 D 段到行动项（梳理过程）

将 ORID 的 D 段从“方向”变成“排期可执行行动项”时，按以下步骤梳理：

1. 对齐目标指标：每个行动项至少绑定 1 个指标（期望改善方向与阈值/趋势）
2. 定义验收标准：用可度量口径描述（例如 p50 降到 X、缺陷数 ≤ Y、review latency p75 ≤ Z）
3. 拆分范围：把大动作拆为可在一个迭代内完成的最小变更
4. 标注依赖与风险：跨团队依赖、工具改造、流程变更阻力等
5. 排期与优先级：先解瓶颈/外溢质量，再优化局部效率；优先做可快速验证的改动
6. 复盘验证：定义下一窗口对比与最低可接受变化，未达标则回到 I 段修正假设

## 每个字段为什么重要

- 编号：用于跨系统追踪与复盘引用，避免“那件事/那个改动”这种口头描述造成上下文丢失。
- 问题：必须能回到 O 段的可复核事实（哪条指标、哪个窗口、哪些样本）。
- 原因：描述机制/流程/协作接口的原因假设，避免把问题归因到个人；建议绑定根因图叶子节点。
- 解决方案：必须是可执行的最小变更（流程/机制/工具/自动化/约束），否则难以落地。
- 责任人：确保推进责任与协调责任清晰；没有责任人的行动项往往会被日常事务吞掉。
- 开始时间：用于识别“做了多久”与“是否在执行”，也用于对齐效果出现的滞后期。
- 发现日期：用于标记趋势起点与影响窗口，帮助选择对比窗口与解释“为什么现在要改”。
- 截止日期：形成时间盒与优先级；没有截止日期，行动项会不断延期。
- 完成日期：用于复盘“什么时候完成”与“效果对比窗口从何时开始算”。
- 预期效果：写成“指标 + 阈值/趋势 + 时间窗”，让改进具备可验证目标。
- 实际效果：记录“结果是什么”，包括副作用与未达预期原因，让下一轮复盘可复用。
- 验收方法：约定如何判定有效（对比窗口、阈值、抽样审计、过程检查点）。
